# BTLO: Eradication

<!-- Original publication date: 2023-12-31 -->

## Introduction

![](../../assets/images/btlo-eradication-001.png)

In this write-up we are going to tackle Eradication.

Difficulty: Easy

Scenario: A threat actor has compromised a system and hidden a number of files. You need to generate a Yara rule to identify the presence of additional binaries based on a collected sample, and then write a custom rule using simple IOCs to identify another type of malware.

Requirements: BTLO VM

Tools: yarGen, yara

Main Files: located in “Investigation” folder

## Question 1: What is the full file path for the rule match in /John/?

Let’s open the README.txt file and see what we need to do:

![](../../assets/images/btlo-eradication-002.png)

Let’s first point yarGen to our malware directory:

``` graf
python3 yarGen.py -m /home/ubuntu/Desktop/Investigation/MALWARE-SAMPLE
```

It appears yarGen generated the rules:

![](../../assets/images/btlo-eradication-003.png)

Let’s run yara with the rules generated by yarGen on John’s directory:

``` graf
yara ../yarGen/yargen_rules.yar /home/John
```

We get the following:

![](../../assets/images/btlo-eradication-004.png)

It appears they found traces of the malware in: */home/John/.bash_history*

> As such, the answer to Question 1 is:

> John/.bash_history

## Question 2: What is the full file path for the rule match in /Trevor/?

Looks like we got something:

![](../../assets/images/btlo-eradication-007.png)

> As such, the answer to Question 2 is:

> Trevor/Downloads/…/…/…/a.a
